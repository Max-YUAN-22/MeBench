Appendix B: Evaluation Protocol, Per-Run Variability, and Reproducibility

B.1 Systems and access configuration

We evaluate six systems spanning three access modes: (i) frontier closed-book models served through a unified relay (GPT-6-Astra, Claude-Sonnet-5.5, Gemini-3.8-Flash, GLM-5.3-Flash, Grok-4.6); (ii) a tool-augmented biomedical agent with retrieval and code execution (Biomni); and (iii) as an ablation, the same agent backbone restricted to single-turn parametric inference without tools. Each system completes four independent passes of the full benchmark. Prompts are byte-identical across systems and passes; sampling temperature is 0.

B.2 Benchmark integrity

All experiments use the frozen benchmark bundle v3.7.0 (27 files), whose SHA-256 manifest ships with the bundle and against which the bundle is verified before each campaign. Unit inputs are distributed to systems; gold mechanism labels, gold mediators, gold causal topologies, and accepted intervention types are held in evaluator-only files and are never visible to evaluated systems or to the prompt templates. The scorer (score_model_outputs.py) is shipped unmodified; the single amendment layer applied anywhere in this work is a designer-approved entity-conditional synonym rule for Task 3 (for regulatory-RNA entities, canonical knockdown is accepted as inhibition), applied identically to all systems and reported with the rescued unit identifiers.

B.3 Metrics

For Task 1 we report accuracy, balanced accuracy, and macro-F1 over the four mechanism classes (chance ≈ 25%). For Tasks 2 and 3, direction (respectively intervention-type) accuracy is accompanied by chain metrics: a unit's five-axis chain passes only if mechanism, mediator, causal order, outcome link, and internal consistency are all adjudicated correct (one-vote veto). Joint pass rate requires the direction (or type) to be correct and the chain to pass; joint F1 is the chain-gated macro-F1 over gold classes; balanced joint accuracy is the per-gold-class mean of joint recall.

B.4 Per-run results and run-to-run variability

Although every run uses temperature 0, serving through relay endpoints is not bit-deterministic, and run-to-run variation is material (Table B2). Claude-Sonnet-5.5's Task 1 macro-F1 ranges from 21.8 to 36.2 across four identically configured runs; GPT-6-Astra's raw accuracy is identical across its four runs (67.8) while its per-class errors migrate between mechanism classes (macro-F1 30.2–40.8). B.5 Chain adjudication protocol and status

Five-axis chain adjudication is performed with the released packet tooling: for each Task 2/3 run, the model's verbatim reasoning is packaged per unit with the task rubric, and a judge model scores five binary axes. Judge assignments are chosen so that no system's outputs are judged by itself (Table B1). Judge outputs are archived verbatim. Two reliability checks support the preliminary judgments: (i) a mediator-axis false-negative audit found 0/193 Task 2 units in which a gold mediator was named in the reasoning yet scored 0; (ii) cross-system agreement on shared units is consistent with per-family failure patterns reported in the main text. All chain and joint values remain preliminary pending blinded human adjudication, for which the review packets are archived; we expect absolute values to shift by a small margin without changes to system ordering.

B.6 Coverage disclosures

  • Chain adjudication coverage per system is stated in Table B2 (footnotes a–d). Unadjudicated runs are excluded from chain/joint means, never counted as failures.
  • Two complementary rules apply. (i) Scoring: outputs are scored exactly as submitted against the canonical matcher, with no output repair; interpretable-but-non-compliant outputs therefore score as incorrect (Claude Task 3 run 2, footnote c — schema-compliant-passes alternative 60.0; GLM Task 2 passes 3–4 input-field echo). (ii) Re-administration: a pass whose outputs are uninterpretable as answers — no answer content recoverable into the prediction file — is an invalid administration and is re-administered once under the identical prompt (GLM Task 1 pass 1, footnote a; GLM Task 2 pass 4, footnote b). Every re-administration and every schema violation is disclosed here and in the frozen audit log.
  • Query–gold consistency check (2026-10-17, designer review). All 193 Task 2 unit inputs were checked against their evaluator-only intervention records. Nine units describe the perturbation abstractly as loss_or_reduction of "target regulatory site(s)"; six of them are genuine CRISPR deletions of the site (direct-cis gold, query consistent). For the three ESR1 enhancer units (T2U_0013–0015) the actual experiment repressed the sites epigenetically (dCas9-KRAB/SIN3A-HDAC, evaluator-only) without altering the DNA sequence, so a literal "site deletion" reading — which all systems adopted — is a defensible interpretation of the query as written. Sensitivity: excluding these three units raises each system's chain-pass rate by 1.1–1.4 pp (e.g. GPT 84.7 → 86.1) and changes no ranking. The units are flagged for dual-key human adjudication (accepting either the direct-cis site-loss reading or the chromatin-mediated reading as mechanism-correct) and for query amendment in the next benchmark revision; primary tables retain the strict original scoring with this disclosure.
  • Task 3 output-schema policy and sensitivity. Task 3 type acceptance uses the canonical matcher, which already merges method-level variants (a bare knockdown is accepted for gold siRNA_knockdown/shRNA_knockdown; 94 unit-runs). Entity-qualified answers, however, are rejected as submitted — in Claude Task 3 run 2, five "miRNA overexpression" answers with gold overexpression and four "miRNA inhibition" answers with gold inhibition (all nine with chain_pass = 1) score 0. Under a semantic-normalization view that accepts these nine, Task 3 joint pass moves from 237/480 = 49.4% to 246/480 = 51.3%, and Claude run 2 from 0/20 to 9/20. Primary tables retain the strict-schema view (consistent with the uniform as-submitted rule) and label such cases schema-compliance failures; the normalized view is reported here as a sensitivity, and a versioned scorer implementing the chosen normalization policy is planned. Task 3's inference target is also not always identifiable from the input alone (agonist vs overexpression; siRNA vs shRNA vs knockout), so the task is framed as a targeted diagnostic subset (20 units, 9 pairs, 6 TFs) rather than a general inverse-inference benchmark.
  • Task 3 comprises 20 units over 9 bidirectional perturbation pairs and is proof-of-concept scale; pass-rate confidence intervals are correspondingly wide (± ~20 pp).
  • One locally deployed open model produced narrative-free outputs that cannot conform to the required answer schema; it is excluded from the v3.7 tables under the format-compatibility criterion, and one additional frontier agent evaluated under the v3.0 protocol was not re-evaluated for the same reason.

B.7 Reproducibility

The released artifact set contains: the frozen benchmark bundle (with SHA-256 manifest), all prompt templates, the unmodified scorer, the disclosed amendment layer with its approval note, per-run prediction files with raw model responses, all adjudication packets and judge outputs, and the aggregation script that produces every published table. Any cell of the main tables can be regenerated with the released tooling, e.g.:

# Task 1 scores for one run (official scorer, unmodified):
python3 score_model_outputs.py --bundle <bundle> --task task1 \
    --predictions <run_dir> --output out.json

# Task 2 with chain judgments:
python3 score_model_outputs.py --bundle <bundle> --task task2 \
    --predictions <run_dir> \
    --reasoning-judgments <run_dir>/task2_judgments.tsv --output out.json

# Task 3 with the disclosed amendment:
python3 score_model_outputs_amended.py --bundle <bundle> --task task3 \
    --predictions <run_dir> --output out.json

Per-run means and standard deviations in Tables B2–B3 are produced by the same aggregation functions that produce the main-text tables; recomputing from the released predictions reproduces every published value.
